1. Platform Overview & Architectural Decisions

This platform is designed as an all-in-one, patient-owned, multi-portal digital healthcare system. Unlike rigid government systems or legacy hospital software, it brings Patients, Doctors, Diagnostic Labs, and Hospitals into a single synchronized ecosystem.

Key Architectural Principles Agreed:
• 100% Standalone & Private: Zero dependency on ABHA / ABDM or government registries.
• Free SMTP Email OTP Authentication: Replaces costly third-party SMS gateways with instant 6-digit OTP delivery to the user's email inbox.
• Direct Local Native Execution: Runs directly via Python virtual environment (venv) and local database — no Docker containers required.
• Frontend-First Architecture: Django data models and API endpoints are mapped directly to match the live Flutter client screens.

3. How Each Dashboard Works & Functions

👤 Patient Portal PATIENT
  • Health Vitals: Real-time tracking of Blood Pressure, Heart Rate, Glucose, and BMI.
  • Medical Records: Central repository for previous doctor notes and prescriptions.
  • Lab Reports: Interactive parameter tables (e.g. HbA1c, CBC counts) with normal/abnormal badges.
  • Unified Timeline: Chronological feed of every healthcare event across all doctors and hospitals.
  • Family Switcher: Manage dependents (children, elderly parents) from a single account.
  • Emergency Info Card: Quick-action card showing blood type, allergies, and emergency contacts.
🩺 Doctor Portal DOCTOR
  • Today's Appointments: Live schedule of patients booked for OPD or consultations.
  • Patient Directory: Fast search by patient name, email, or generated patient ID.
  • Clinical Chart: Review comprehensive past medical history, previous diagnoses, and vitals.
  • Allergy & Condition Warning Chips: Prominent alerts for drug allergies (e.g. Penicillin) before prescribing.
  • E-Prescription & Diagnosis Form: Prescribe medicines with dosage (e.g. 1-0-1) and instructions.
  • Instant Patient Locker Sync: Issued prescriptions instantly reflect in the patient's personal locker.
🧪 Diagnostic Lab Portal LAB
  • Pending Queue: Categorized test orders (Biochemistry, Endocrinology, Cardiology, Diabetology).
  • Parameter Entry: Technician enters observed values alongside biological reference intervals.
  • PDF Attachment: Option to attach official lab report documents.
  • Auto-Publish: Submitting a test result updates the patient's app and dispatches an alert.
  • LIMS Integration Gateway: Ready for real-time automated data-push from existing lab machines.
🏥 Hospital Care Portal HOSPITAL
  • Inpatient Bed Occupancy: Live stats across General Wards, ICU, Private, and Semi-Private rooms.
  • Admission Intake: Admit patient, assign ward, bed number, attending physician, and initial diagnosis.
  • Active Ward Management: Filter and track inpatient stability and length of stay.
  • Discharge Summary: Final diagnosis, treatments administered, home care advice, and follow-up date.
  • HIS Gateway: HL7 ADT protocol-ready connection monitor.

4. Authentication Workflow: Free Email SMTP OTP

To eliminate costly SMS gateway APIs, the authentication engine uses direct SMTP Email OTP. Both Login and Signup follow a clean, unified flow: 

┌─────────────────────────────────────────────────────────────────────────────┐
│                       STEP 1: USER ENTERS EMAIL                             │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│         STEP 2: BACKEND SENDS 6-DIGIT OTP VIA FREE GMAIL/CUSTOM SMTP        │
│          (OTP is generated securely in memory with a 5-minute expiry)       │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                 STEP 3: USER ENTERS OTP IN FLUTTER APP                      │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       ▼
                     Is user already registered in PostgreSQL?
                                ├───► YES: Issue JWT ──► Route to User's Role Dashboard
                                └───► NO:  Prompt Role Selection (Patient / Doctor / Lab / Hospital)
                                           Collect details ──► Save Profile ──► Route to Dashboard
Why Unified Login is Best

Users never have to guess which login URL to use. One simple screen accepts any valid email. The backend automatically detects whether the user is a patient, doctor, or lab manager and launches the exact corresponding dashboard.

Hybrid Role Switching

Healthcare professionals are patients too. Doctors can seamlessly switch between treating patients in the Doctor Portal and managing their own personal and family health records with a 1-tap role switcher.

6. Django REST Backend API Endpoints (Sprint 1 & 2)

Method Endpoint Description
POST /api/auth/request-otp/ Generates 6-digit OTP and sends it via SMTP email to the user.
POST /api/auth/verify-otp/ Verifies email OTP, checks registration status, issues JWT tokens.
POST /api/auth/register-profile/ Completes profile registration with selected role and license/facility info.
GET /api/patients/me/ Fetches logged-in patient vitals, emergency card, and profile metadata.
GET /api/records/ Lists all medical records, prescriptions, and timeline events for the patient.
POST /api/records/add/ Creates a new clinical record / prescription entry.
GET /api/reports/ Lists diagnostic and lab reports with structured test parameters.
POST /api/doctor/diagnose/ Doctor endpoint to save primary diagnosis and dispatch e-prescription to patient.
GET /api/hospital/admissions/ Lists active inpatient ward admissions and bed occupancy states.
POST /api/hospital/admissions/new/ Admits a new patient to a specified hospital ward and bed.
